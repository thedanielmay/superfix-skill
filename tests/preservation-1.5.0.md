## Deviations from the plan (builder, 19 Oct 2026)

Each is the smallest honest reading of the plan (`PLAN-superfix-1.5.0.md`, with its "Panel changes" section winning over earlier text), or a fix for something its wording would have broken. All tools were tested under a fake HOME on the local `seed-1.5` fixtures (72 command tests); no model run, no GitHub write, no real `~/.superfix`.

Tool
- **One tool, `crit.py`, instead of separate one-line commands.** criteria.md carries a standard-library script between `# --- crit.py start ---` and `# --- crit.py end ---`, written into the run folder by an `awk` command, as `shot.py` is in evidence.md. Subcommands: `shape`, `measure`, `lock`, `lockcheck`, `attempt`, `progress`, `comment`, `where`, `copy`, `finish`, `index`. Reason: the checks compare numbers across files (comment, attempts, outputs), which a zsh one-liner cannot do safely. So criteria.md is about 850 lines, not the plan's "about 190"; the rules part is about 300.
- **Extra words** beyond the plan's list: `CRIT-READY`, `EXPECTED`, `UNEXPECTED`, `ATTEMPT-SAVED`, `ATTEMPT-REFUSED`, `MOVED`, `NO-PROGRESS`, `PROGRESS-NONE`, `STOP-NO-PROGRESS`, `STOP-CAP`, `PATH-CLOUD`, `PATH-LOCAL`, `ASK-FIRST`, `COPY-READY`, `COPY-EXISTS`, `COPY-REFUSED`, `ORIGINAL-UNCHANGED`, `ORIGINAL-CHANGED`, `WORK-KEPT`, `WORK-DELETED`, `WORK-NONE`, `INDEX-ADDED`, `INDEX-REMOVED`, `INDEX-NOT-LISTED`, `INDEX-REFUSED`; `CRITERIA-BAD` also names `date` and `approver`. The redaction.md line is c11's word for word; it points at criteria.md, which lists the rest.
- **The runner computes the data file's sha256 itself.** A `DATA-SHA` line that differs from it is `ERROR`, so the recorded sha is the file actually measured, not what the script claims. The script's own error text is never printed (a traceback can quote a row).

Wording and shape
- **Examples are the first 3 `ITEMS`.** The plan says both "up to 3 examples" and "ITEMS equal to the examples", which cannot both hold with 8 duplicate rows. Rule: the script lists every row in ascending order; the plain block shows its first 3; the comment check compares exactly those.
- **Every criterion line has a plain name followed by a colon.** The plan's K example had a comma after the name, and its P2 and P3 examples had no name. Names are letters, digits, spaces and hyphens, starting with a letter, unique per issue, because the `Criteria check:` line is comma separated and a name starting `8. ` would break the COUNT check. Examples in criteria.md: "refund time", "mileage claim".
- **A dd/mm style date in a criterion line is `CRITERIA-BAD <id> date`**, so `03/04/2025` can only reach the owner as a numbered question.
- **The comment check compares numbers at fixed places only**: the plain line's Today number and examples, the `Criteria check:` values and result word, the final table's before and after cells, and the newest attempt line against its output files. "Every number" would wrongly flag the pass line's own number ("Must be 0").
- **A criterion's value is compared with the newest attempt line that has it**, because a `later` criterion is not re-measured in run 2.
- **The attempt line adds `from <out>`** (the output folder it was made from), so the comment check can compare it with those files. With several measured files, `data-sha` is the sha256 of their sorted shas.
- **The no-progress stop text when nothing got worse** reads "Two tries did not get closer: <name> went from 8 to 8. ..." (the plan's text assumes something got worse).
- **`Criteria check:` in code-only runs** reads `NONE (no Everything else problem)` in the journal.md templates, because c7 says every stop message and final comment carry the line. Code-only runs still never load criteria.md or run its tool.
- **c1's example** keeps the plan's illustrative "rows 14, 15, 88" word for word; the fixture's real first rows are 14, 15 and 62 (criteria.md and README use those).

Behaviour
- **The reminder question has NO recommended answer** (plan D4 B), as the release issue says ("Reminders for later checks, only on a yes") and the coordinator asked. Anything but an explicit yes to it is no, like the create-issue question; "keep executing" never creates a task. The task goes to the `@default` list. The `gws tasks tasks insert` command was validated with `--dry-run` only; nothing was created.
- **Copy mode, added to execute.md's Criteria mode sequence** (found by the advisor review, not in the plan): outside a PRIVATE git repo that is not in a cloud mount there is no branch, commit or PR; plan and context files go in `~/.superfix/journal/<name>/`, as for Qik; budget commits count only in git. Without this, N6 and N10 would run `git switch -c` or write `docs/superpowers/plans` where they must not. With no PR, the issue closes after the owner's reply (criteria.md section 17).
- **The run folder stays while the owner still has to put a copy back.** redaction.md deletes the run folder at the end of the run, which would delete the very copy the owner needs (a Sheet or a no-git file). criteria.md section 9: the job has not ended, so `work/` stays (mode 700 and 600, this Mac only) until the export is measured or the owner says stop; then `finish`, then the delete. `finish` keeps `work/` (`WORK-KEPT`) and asks if an original changed during the run.
- **The cloud list** adds `~/Library/Mobile Documents`, `~/Google Drive` and `~/OneDrive` to the plan's mounts, and follows symlinks (a `~/shared-drives` link into CloudStorage is caught).
- **MCP file tools:** besides the named tool words, criteria.md section 11 bans any MCP tool that creates, changes, moves or deletes a file or a record anywhere.

Not done here (other tasks): probes P1 and P2, the S13 synthetic `run.jsonl` test and `check150.py` (T2 testbed work), every model test (T8). Fixtures are local only: `seed15/overlay/` (one local commit, never pushed) and `seed15/nogit-fixture/stock.csv` (the plan named `scratchpad/nogit-fixture/`).
