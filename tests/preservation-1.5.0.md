## Deviations from the plan (builder, 19 Oct 2026)

Each is the smallest honest reading of the plan (`PLAN-superfix-1.5.0.md`, with its "Panel changes" section winning over earlier text), or a fix for something its wording would have broken. All tools were tested under a fake HOME on the local `seed-1.5` fixtures (72 command tests); no model run, no GitHub write, no real `~/.superfix`.

Tool
- **One tool, `crit.py`, instead of separate one-line commands.** criteria.md carries a standard-library script between `# --- crit.py start ---` and `# --- crit.py end ---`, written into the run folder by an `awk` command, as `shot.py` is in evidence.md. Subcommands: `shape`, `measure`, `lock`, `lockcheck`, `attempt`, `progress`, `comment`, `where`, `copy`, `finish`, `index`. Reason: the checks compare numbers across files (comment, attempts, outputs), which a zsh one-liner cannot do safely. So criteria.md is about 850 lines, not the plan's "about 190"; the rules part is about 300.
- **Extra words** beyond the plan's list: `CRIT-READY`, `EXPECTED`, `UNEXPECTED`, `ATTEMPT-SAVED`, `ATTEMPT-REFUSED`, `MOVED`, `NO-PROGRESS`, `PROGRESS-NONE`, `STOP-NO-PROGRESS`, `STOP-CAP`, `PATH-CLOUD`, `PATH-LOCAL`, `ASK-FIRST`, `COPY-READY`, `COPY-EXISTS`, `COPY-REFUSED`, `ORIGINAL-UNCHANGED`, `ORIGINAL-CHANGED`, `WORK-KEPT`, `WORK-DELETED`, `WORK-NONE`, `INDEX-ADDED`, `INDEX-REMOVED`, `INDEX-NOT-LISTED`, `INDEX-REFUSED`; `CRITERIA-BAD` also names `date` and `approver`. The redaction.md line is c11's word for word; it points at criteria.md, which lists the rest.
- **The runner computes the data file's sha256 itself.** A `DATA-SHA` line that differs from it is `ERROR`, so the recorded sha is the file actually measured, not what the script claims. The script's own error text is never printed (a traceback can quote a row).

Wording and shape
- **Examples are the first 3 `ITEMS`.** The plan says both "up to 3 examples" and "ITEMS equal to the examples", which cannot both hold with 8 duplicate rows. Rule: the script lists every row in ascending order; the plain block shows its first 3; the comment check compares exactly those.
- **Every criterion line has a plain name followed by a colon.** The plan's K example had a comma after the name, and its P2 and P3 examples had no name. Names are letters, digits, spaces and hyphens, starting with a letter, unique per issue, because the `Criteria check:` line is comma separated and a name starting `8. ` would break the COUNT check. Examples in criteria.md: "refund time", "mileage claim".
- **A dd/mm style date in a criterion line is `CRITERIA-BAD <id> date`**, so `03/04/2025` can only reach the owner as a numbered question.
- **The comment check compares numbers at fixed places only**: the plain line's Today number and examples, the `Criteria check:` values and result word, the final table's before and after cells, and the newest attempt line against its output files. "Every number" would wrongly flag the pass line's own number ("Must be 0").
- **A criterion's value is compared with the newest attempt line that has it**, because a `later` criterion is not re-measured in run 2.
- **The attempt line adds `from <out>`** (the output folder it was made from), so the comment check can compare it with those files. With several measured files, `data-sha` is the sha256 of their sorted shas.
- **The no-progress stop text when nothing got worse** reads "Two tries did not get closer: <name> went from 8 to 8. ..." (the plan's text assumes something got worse).
- **`Criteria check:` in code-only runs** reads `NONE (no Everything else problem)` in the journal.md templates, because c7 says every stop message and final comment carry the line. Code-only runs still never load criteria.md or run its tool.
- **c1's example** keeps the plan's illustrative "rows 14, 15, 88" word for word; the fixture's real first rows are 14, 15 and 62 (criteria.md and README use those).

Behaviour
- **The reminder question has NO recommended answer** (plan D4 B), as the release issue says ("Reminders for later checks, only on a yes") and the coordinator asked. Anything but an explicit yes to it is no, like the create-issue question; "keep executing" never creates a task. The task goes to the `@default` list. The `gws tasks tasks insert` command was validated with `--dry-run` only; nothing was created.
- **Copy mode, added to execute.md's Criteria mode sequence** (found by the advisor review, not in the plan): outside a PRIVATE git repo that is not in a cloud mount there is no branch, commit or PR; plan and context files go in `~/.superfix/journal/<name>/`, as for Qik; budget commits count only in git. Without this, N6 and N10 would run `git switch -c` or write `docs/superpowers/plans` where they must not. With no PR, the issue closes after the owner's reply (criteria.md section 17).
- **The run folder stays while the owner still has to put a copy back.** redaction.md deletes the run folder at the end of the run, which would delete the very copy the owner needs (a Sheet or a no-git file). criteria.md section 9: the job has not ended, so `work/` stays (mode 700 and 600, this Mac only) until the export is measured or the owner says stop; then `finish`, then the delete. `finish` keeps `work/` (`WORK-KEPT`) and asks if an original changed during the run.
- **The cloud list** adds `~/Library/Mobile Documents`, `~/Google Drive` and `~/OneDrive` to the plan's mounts, and follows symlinks (a `~/shared-drives` link into CloudStorage is caught).
- **MCP file tools:** besides the named tool words, criteria.md section 11 bans any MCP tool that creates, changes, moves or deletes a file or a record anywhere.

Found in a self-review of the whole flow (fixed in the "review fixes" commit; 84 command tests)
- **c1's example now has criteria.md's shape**: `"Duplicate members. Today: 8 (rows 14, 15, 62). Must be 0."` (the plan's `"Today: 8 duplicate rows (rows 14, 15, 88)..."` had no plain name, so a model copying it would fail the comment check). c1 is new in 1.5.0, so no preservation line. The check also accepts words between the number and the examples ("Today: 8 duplicate rows (rows 14, 15, 62).").
- **A problem with only `owner` criteria** has no scripts and no attempts; `comment` no longer demands an attempts file for it and still checks its lines; `lock` works with no scripts.
- **A version is never counted twice:** `attempt` prints `ATTEMPT-SAME <n>` and writes nothing when the file and values equal the newest line (run 2 measures the same file as the last try). **A version where every `check` criterion passes is `CHECKS-PASS <n>`**, never `NO-PROGRESS`, `STOP-NO-PROGRESS` or `STOP-CAP`.
- **The lock line reads `Internal: criteria-sha <64 hex> (sha256), locked ...`**: redaction.md's pattern check passes a 64-hex string only on a line holding `sha256`; without it every body update after go printed `PATTERN-HITS` and a model following "unsure: redact" would break the lock (`CRITERIA-UNLOCKED`). Shas in comments are written `sha256 <hex>` for the same reason. redaction.md is unchanged. Tested with redaction.md's own pattern command.
- **After `RUN-MOVED`** (create-issue yes) the criteria folder moves to the issue key before the lock (`CRITERIA-FOLDER-MOVED`, `REFUSED-EXISTS`, `CRITERIA-FOLDER-NONE`).

Not done here (other tasks): probes P1 and P2, the S13 synthetic `run.jsonl` test and `check150.py` (T2 testbed work), every model test (T8). Fixtures are local only: `seed15/overlay/` (one local commit, never pushed) and `seed15/nogit-fixture/stock.csv` (the plan named `scratchpad/nogit-fixture/`).

## Review 1 (19 Oct 2026)

Independent review 1 found 18 problems; the coordinator verified them and decided each one. The builder checked every finding against the code before fixing: all 18 were real (item 17 was a live bug: a relative `--script` path broke once the runner changed folder). Every fix is in `crit.py` (criteria.md) unless named, and each has at least one command test (211 in all, fake HOME, all passing; the 84 earlier tests are kept on the new argument forms, four renamed: `decision-result` is now `decision-verdict-recomputed`, `c1-shape-ok` and `decision-pass-number-ignored` are covered by `decision-ok`, and `c1-words-ok` became `plain-words-rejected` because item 3 now rejects words in the plain line).
1. **Lock at run time.** `lock` takes `--data` (each original) and `--attempts`, writes `<criteria folder>/lock` (hash, each script's sha, each data path) and refuses when an output used by the current epoch was measured with another script version. `measure` refuses a script that is not `measure-<id>.py` in the criteria folder (`ERROR-SCRIPT-NOT-LOCKED`) and, after go, any lock mismatch (`CRITERIA-CHANGED`) or data that is neither a locked original nor in `work/` (`ERROR-DATA-NOT-LOCKED`). `attempt`, `progress`, `comment` and `lockcheck` verify every recorded `SCRIPT-SHA` and data path behind the attempt lines.
2. **Verdict by the tool.** Scripts print only `MEASURE` and `ITEMS`; the tool computes PASS or FAIL from the number and the pass line; a script verdict that disagrees is `ERROR-VERDICT-DISAGREES`; any other output line is an error and is never shown. The comment check recomputes every verdict (`comment PASS computed FAIL`).
3. **Plain line.** Exactly `<plain name>. Today: <n> (rows N, N and N). Must be <pass line>.`; the bracket holds only row numbers, and `Must be` must equal the locked pass line (`CRITERIA-PLAIN-BAD`). A personal-data scan (`CRITERIA-PII`: e-mail, phone-like number with 8 or more digits, link, 9 or more digits) runs over the plain lines, the `Criteria check:` line and the table rows; ISO dates are not phone numbers. redaction.md gains one line naming it. Deviation: the scan covers only those criteria lines, not the whole comment, because the comment's AI detail legitimately holds links (the issue link, the gap list link).
4. **Pass-line grammar** as decided (table in criteria.md section 2), plus `yes` and `no` (the plan's "yes or no fact") and a trailing note in brackets without digits (`112 (today's count)`). `N% fewer than today` is floor(baseline x (1 - N/100)), rounded down; `fewer than N` counts as below N; compound or unknown lines are `CRITERIA-VAGUE`. The plan's own P2 example (`3 or fewer over at least 20 refunds`) is compound, so criteria.md now puts "at least 20 refunds" in the definition and the script exits non-zero until it holds. The reviewer's own examples were not passed to the builder; the tests cover every grammar form plus 14 vague ones (`under 3`, `3-5`, `3 days or fewer`, `0 (or 1)` ...) and the verdict of each form.
5. **Checkboxes** are read as `[ ]` in the lock hash; the new `signoff` command records ticks as `signoff <date> <id> <k>/<n>` lines.
6. **Epochs.** The attempts file starts `epoch 1`; `attempt --new-epoch` starts the next. Line 0 of the current epoch is the baseline everywhere; under a new lock `attempt` refuses until `--new-epoch`; old epochs stay. Attempt lines gain `lock <criteria-sha or none>`.
7. **Sandbox.** Probed first: `sandbox-exec` with a profile denying network and every write outside a temporary folder blocked both (PermissionError). `measure` runs scripts under it with `python3 -I -B`, a cleaned environment and the 120 second limit; without it, `SANDBOX-MISSING` and nothing runs until the owner answers a numbered question with no recommended answer (`--unsandboxed-ok`). The test switch `SUPERFIX_TEST_NO_SANDBOX=1` can only make the sandbox look missing, never skip it. `ASK-FIRST` now also applies to `measure` and to `finish`'s hashing, and covers online-only (dataless) files.
8. **Never-send** is a principle plus the decided routes (criteria.md section 11; SKILL.md's c1 line shortened to the principle). The S13 check is now the `sendcheck` command, tested on a synthetic log with 13 routes (gws send, copy_file, a Write into a cloud folder, Artifact publish, Claude Docs batch, curl `--data-binary`, nc, scp, gh gist, cp and Python writes into a cloud path, a Qik write, a Gmail send inside a subagent event): 13 hits; a clean log of reads gives none, and a `git push` gives `SEND-REVIEW`. Honest limit: the Bash patterns are text matches, so an unusual spelling can pass; the test flags in check150.py remain the hard guard.
9. **Cloud check** adds iCloud Drive and, when `com~apple~CloudDocs/Desktop` or `Documents` exists, `~/Desktop` and `~/Documents`; real paths, compared ignoring case.
10. **Data never committed by default, on any repo**; committing needs a numbered question (exact text in criteria.md section 4) on a repo `visibility` reports PRIVATE. New `visibility` command; a failed or unknown read is PUBLIC. The undo line for a branch says GitHub keeps a closed PR's commits. SKILL.md's c1 line, execute.md's copy-mode line and README follow. Documents with no personal data may still go on a branch in any repo.
11. **No checkable criterion**: stop at diagnosis and a gap note of kind "no checkable criterion"; SKILL.md's gap-note line, gaps.md line 7 and the template option now say the same (justifications above amended).
12. **`Refs`** whenever any non-code problem has a `later` or `owner` criterion, is a process, or still matches the description: SKILL.md Phase 4 (c6 line reworded, still one line) and criteria.md section 16.
13. `ERROR-ITEMS-OUT-OF-RANGE` when a row number exceeds the file's row count (CSV records, header included).
14. Final table: every cell has a fixed form (numbers; `LATER <date>` after for `later`; `OWNER` for `owner`); anything else is `TABLE-CELL-UNCHECKED`; `must be` must equal the pass line and the result the computed verdict.
15. **Export**: copied into `work/` with its own sha (`copy --name export-<date>.<ext>`), measured there; the owner is told to delete his export himself. Superfix never deletes his files.
16. `index` takes a `mkdir` lock (`INDEX-BUSY` after 10 seconds) and refuses `|`, quotes, `$`, backticks, backslashes and control characters in `--job` and `--waits`. The reminder is the new `remind` command, which builds the gws request with `json.dumps` and refuses unsafe text (tested with `--dry-run` only, which gws validates locally).
17. Every path argument is resolved to its real path before the tool changes folder (tested with relative paths from another folder).
18. **Negative control** (`measure --neg-of <change> --defect <words>`): `ERROR-NEG-NOT-DISTINCT` when the copy equals the change or an original, `ERROR-NEG-NOT-ONE-DEFECT` unless exactly one row is added, removed or changed, and a `neg` line in the attempts file.
- **Question order** (criteria.md section 4, journal.md): the criteria questions, the sandbox and data-commit questions when they apply, the budget question, then the diagram, reminder and `assets` questions, and the create-issue question last.
- SKILL.md stays 417 lines: every SKILL.md change is a reworded 1.5.0 line in place.
