## Deviations from the plan (builder, 19 Oct 2026)

Each is the safest reading of the plan, or a fix for something the plan's wording would have broken. Found while verifying `shot.py` locally on testbed tag `seed-1.4`.

- **Window scroll, not `scrollIntoView`.** The plan (C5) says `scrollIntoView({block:"center"})`. On `public/pricing.html` that also scrolled the `overflow:hidden` price card and showed the whole Subscribe button, so the picture hid the very bug. `shot.py` scrolls the window only (`window.scrollBy`), and evidence.md says why.
- **`--hide '<css>'` option.** D4 step 3 says the run hides an unreachable element (`visibility:hidden`) and tries again; before approval no tracked file may change, so the script does the hiding itself, in its own browser page. A `--hide` selector that matches nothing prints `ERROR`.
- **Picture area:** the target plus 320 px left and right and 200 px above and below, clamped to the 1280 by 800 viewport (the plan gave no figure). With 160 px the account page's labels and values were cut off.
- **Blanking also covers the `value` attribute**, open shadow roots and same-origin frames; **unreachable kinds also include `object` and `embed`**; after blanking, the script stops with `ERROR` if any secret is still in the page text.
- **The script is written into the run folder by an `awk` command from evidence.md**, not typed out by the model, so it cannot be mistyped. It is identical to the block in evidence.md (checked with `diff`).
- **Extra subcommands:** `pair` (the D7 `magick` command, and it copies the before picture's side file to the pair), `mcp-code` and `mcp-save` (the MCP path uses the same blanking, marking and scanning code, generated by the script; `mcp-code` refuses when the secrets list has any entry). On the MCP path the side comes back in a tool result, so its Viewed line is a self-report, as D3 already says. Tested in Node with playwright-core 1.64 (the version the Playwright MCP uses), not inside the MCP's `browser_run_code` itself.
- **Viewed line wording:** `Viewed: label <n> <red|green>, <right of|left of|below> <target>` ("below of" is not English). `verify` also fails a Viewed line older than the picture (a stale line after a retake). The side file holds side, colour and number.
- **The upload command has a mode `A='upload'` or `A='keep'`.** `keep` (public repo, or no issue) runs the same checks and copies only a clean picture to `~/.superfix/journal/<owner>-<repo>/pictures/<run-key>/`, so a picture that failed a check is never kept outside the run folder. New words: `KEPT`, and the command also prints `NO-RUN-FOLDER` and `NOT-VIEWED`.
- **No issue (file-mode journal):** pictures are kept locally like a public repo; if the owner says yes to creating the issue on a PRIVATE repo, they are uploaded after `gh issue create`. The plan named file-mode picture names but not where they go.
- **Two extra Not tested lines:** magick missing; the `assets` release still waiting for the owner's yes.
- **evidence.md is 531 lines, not about 220:** the script is 360 of them.
- **C4 position.** The plan puts the SKILL.md pictures sentence on a new line right after the line starting "Pattern hits are only reported and you decide: code reading a variable". That line is the first half of a sentence, so a line there would split it. The sentence goes at the end of the same paragraph (same section, "Decision and redaction").
- **One extra SKILL.md line** in the agent dispatch list: the fix agent gets the absolute path of evidence.md and the interpreter, because briefs.md says "absolute path given". SKILL.md is 429 lines.
- **Count check:** the callout states the number in digits; the command counts numbered lines above the `---` only, so the AI detail's numbered lists do not count; the Simple short form is exempt.
- **Cost line figures by tier** (Simple about 2 USD, Moderate about 6, Complex about 15) are rough and not measured; the T14 test record should replace them.
- **Test note:** testbed `seed-1.4` plants the token five ways (a text node, input `token_field`, input `field2`, a `<code>` element, a canvas), not four, so prompt 10 expects four `[redacted]` token copies plus the blanked e-mail, and the canvas blocked or hidden.
