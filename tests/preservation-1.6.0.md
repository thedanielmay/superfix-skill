## Deviations from the plan (builder, 20 Oct 2026)

Each is the smallest honest reading of the plan, or a fix that Phase 0 or a free test showed was needed.
- **The three commands are `crit.py` subcommands**, not shell blocks in workorder.md: `sandbox`, `wo-check` (WORKORDER), `wo-baseline` (BASELINE), `wo-lock`, `wo-return` (RETURN), `wo-verify` (Superfix's own runs at H) and `wo-files` (the files row). Reason: BASELINE and RETURN run someone else's code in the sandbox, and `profile()` lives only in `crit.py`. `crit.py` is the existing tool, so no new tool is added, and workorder.md stays at 140 lines (plan target 209, cap 250).
- **The widened sandbox needs two more rules than the plan named**, found by probing: `(allow process-fork)` (bash starts the tools check.sh calls) and `(allow sysctl-read)` (node aborts at once without it). The allowed programs' own files are also readable, so bash can find `tr`, `cut`, `sed` and `grep`. With no programs added, `profile()` returns the 1.5.0 string byte for byte; the 427 criteria-mode command tests pass on the 1.6.0 `crit.py`. P2 passes: the example check.sh gives the same six results at the base as outside the sandbox; curl, a read of `~/.ssh`, node's network and writes outside the temporary folder are blocked.
- **Phase 0 template fixes** (from `phase0-results.md`):
  - FILES marks every file that does not exist at BASE with ` (new)`. Rules 2 and 4 say so, and Step 0 checks that each unmarked file exists (PLAN-MISMATCH names it). `wo-check` prints `WORKORDER-FILE-NOT-AT-BASE` and `WORKORDER-NEW-EXISTS`.
  - Step 0 runs as `bash <<'STEP0' ... STEP0`, whatever the shell, with FILES in bash arrays. Tested under zsh and bash: the STALE check now fires under both.
  - Step 0 prints the three loop commands (attempt, count, bundle) with literal paths, because the shell keeps no variables between calls.
  - Step 0 clones into a new `mktemp -d` folder each time (review fix 2 replaced the earlier refusal of a leftover clone, which forced every send-back to restart at BASE).
  - Loop step 1 says "commit at once, with no change in between" (E1-sonnet-4 changed code after its check run).
- **Steps 2 and 3 of the example template are reworded**: `Error("unknown format: <name>")` and `` `unknown format: <value>` `` would fail the plan's own WORKORDER rule (no `<...>` outside the Report). The CHECKS block, and so CHECKS-SHA `fa15474e...`, is unchanged.
- **Extra words**:
  - `WORKORDER-NOT-IN-BASELINE`, `WORKORDER-STEP0`, `WORKORDER-FILE-NOT-AT-BASE`, `WORKORDER-NEW-EXISTS`;
  - `WORKORDER-LOCKED`, `WORKORDER-LOCK-REFUSED`, `WORKORDER-DEST-NOT-EMPTY`, `WORKORDER-COPY-FAILED`;
  - `RETURN-NO-WORK`, `RETURN-BUNDLE-BAD`, `RETURN-NO-BRANCH`, `RETURN-PATCH-FAILED`, `RETURN-CHECKED`, `RETURN-FILES`, `RETURN-IGNORED`;
  - `VERIFY-PASS`, `VERIFY-FAIL`, `TESTNAMES-OK`, `SANDBOX-EXIT`, `SANDBOX-NO-NODE`.
- **`RETURN-CAP`** at exactly 5 attempts is printed beside `RETURN-OK` (no send-back is left), as the plan's free test "5 attempt commits and a Report claiming 2 prints RETURN-CAP" needs; over 5 it is a stop, and `wo-sendback` refuses at 5 (review fix 2).

- **Redaction:** the pattern check always reports the template's two 64-hex sha lines (`CHECKS-SHA:` and Step 0's sha compare), because neither holds the word `sha256`. workorder.md says these are decided as shas; a planted token is still caught (tested).

## Review fixes (two Opus reviews, 20 Oct 2026)

- **Forged pass:** `sandbox` and 1.5.0's `run_script` share `run_capped` (pipe, 16 MB read cap, RLIMIT_FSIZE 256 MB). `wo-verify`, `wo-baseline` and `wo-solved` parse each locked script's run on its own: exactly one CHECK line per BASELINE id (check.sh) and per held-back id (from the locked held.sh's own `r` calls), no unknown id, exit 0; a timeout, overflow or crash is `VERIFY-PROBLEM`. `wo-verify` gains `--timeout`.
- **Send-back loop:** the executor ticks and reports in `report.md`; workorder.md is never edited, so Rule 0's sha holds in every round. New command `wo-sendback` writes a fresh folder (the same locked workorder.md, the last returned work as `return.bundle`, `sendback.md` with Superfix's own FAIL lines, held-back ones by id only) and refuses at the cap (`RETURN-CAP`) or when Superfix's failing count did not fall (`NO-PROGRESS`). Step 0 carries on from `return.bundle`. Every return is recorded in `D/workorder/rounds.json` (H, attempts, Superfix's failing count); attempts are the larger of the git count and the last recorded attempts plus one, and a later H must descend from the last one (`RETURN-NOT-BUILT-ON`). Known limit: a squash inside round 1 cannot be seen from git.
- **Links:** any symlink or hard link in a returned folder stops `wo-return` and `wo-files` (`RETURN-SYMLINK`), after the shared lock steps, which `wo-files` now runs too (it gains `--issue`/`--body`). Files are copied with `follow_symlinks=False`.
- **wo-lock** runs WORKORDER and BASELINE itself (gains `--clone`) and refuses unless both are OK. **wo-return** runs `git ls-remote origin <BRANCH>` (`RETURN-PUSHED`, or `RETURN-REMOTE-UNCHECKED` when it cannot look). **tap_names** reads indented TAP lines (tests in describe blocks); a missing held.sh is `VERIFY-FAIL`. **held.sh and check.sh go into the sandbox as text** (`bash -c`), so no run-folder path is added to the sandbox's read list. **wo-verify** also compares the suite (`SUITE-NEW-FAILURES`); new command **wo-solved** runs SKILL.md's solved check runs 1 and 3 in the sandbox, where a crash never counts as the expected failure.
- **D2 default destination changed:** from `~/.superfix/journal/<owner>-<repo>/workorders/<id>/` to `~/superfix-workorders/<id>/`, outside `~/.superfix`, because a same-Mac executor in the journal sits beside the run folder (held.sh, the lock, crit.py). `wo-lock` and `wo-sendback` refuse a folder inside `~/.superfix` (`WORKORDER-DEST-INSIDE-SUPERFIX`); workorder.md says a local executor runs as another user or sandboxed. The locked copies, held.sh and the ## Decision shas stay in the run folder and journal.
- **Step 0 prints its three commands with `printf %q`**, so a folder or TMPDIR with a space or an apostrophe still pastes (tested under zsh and bash).
- **SKILL.md** Work order mode gains "No workorder.md read, no work order: run as normal." on an existing line (426 lines).
